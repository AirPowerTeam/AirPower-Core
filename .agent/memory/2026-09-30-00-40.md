## 关键发现（P0，务必记住）

1. **RootModel.desensitize() 对嵌套模型完全失效**。白名单判定用 `this.getClass()`，
   递归时 `this` 已是子对象，条件不成立就直接 return，`isDesensitize` 分支不可达。
   后果：嵌套结构中的手机号/身份证以明文返回。现有单测之所以通过，是因为夹具里
   嵌套模型与外层都是 DemoModel，恰好落在白名单内。修复：拆出独立的
   `desensitizeAll` 深度遍历，不用类白名单，并用 IdentityHashMap 防自引用栈溢出。

2. **ReflectUtil 在 finally 里 setAccessible(false)**。该标志是 Field 的全局状态，
   线程 A 设为 true 后被线程 B 清掉，A 的 field.get 立即抛异常。8 线程 × 2000 次
   稳定复现。同时让 getCacheFieldList 里的 setAccessible(true) 完全白做。
   修复：直接移除 finally；setFieldValue 改为抛 ServiceException 而非只记日志。

3. **多 Locale 交叉验证揪出隐蔽缺陷**。ReflectUtil.getFieldGetter 用无 Locale 的
   `toUpperCase()`，土耳其语环境下 `getId` 被拼成 `getİd`，导不到方法，
   导致 @Export/@Meta 注解查找全部失效——tr_TR 下导出的 9 列掉到 8 列。
   RandomUtil 同样问题。只跑默认 Locale 完全发现不了。

## 方法论（下次扫描可复用）

- **先写探针再下结论**。用临时 @Test 打印实际行为，避免"看起来是 bug"改错方向。
  验证完删掉探针文件。
- **测试断言旧缺陷行为时，改动前先问"这个断言在保护什么"**。本次有 20+ 个用例
  固化的是缺陷行为（如"floor(-1.5,0) 应为 -1"），修复后要逐条改成断言正确行为，
  并在 DisplayName 里写明"不再……"的原因。
- **多 Locale × 多时区跑全量**是性价比最高的检查手段，揪出了 4 个单 Locale 下
  永远发现不了的问题。
- **回归用例必须逐个验证"能变红"**。补完用例后把缺陷重新注入源码
  （恢复 `setAccessible(false)`、删掉 `.timeout()`、把缓存 key 改回类名），
  确认对应用例确实失败再恢复。没验证过的回归用例可能根本不测任何东西。

## 测试补强阶段的关键发现

### `@NotNull` 参数的异常类型依赖编译方式（重要）

同一个 `@NotNull` 参数传 null，异常类型取决于谁编译的 class：

- Maven `javac` → 不做运行时检查，方法体内解引用抛 `NullPointerException`
- IDEA 开启 *Instrument code with @NotNull assertions* → 提前拦截抛
  `IllegalArgumentException`（字节码里能看到 `$$$reportNull$$$0`）

后果：断言精确异常类型的用例在 `mvn clean test` 下全绿，但只要 class 是 IDEA 编的
（典型触发：加 `-DargLine` 跑多 Locale / 多时区），必然失败。
**断言要锁"契约"而非"异常类型"**——这里该断言的是"未做判空会失败"，不是"抛哪种异常"。
用 `javap -p Xxx.class | grep reportNull` 可确认当前产物是否被插桩。

## 踩过的坑

- `RootModel` 里跨实例调用 private 方法编译不过（`itemModel.handleNested()`），
  改成 `private static void handleNested(RootModel<?> nested, ...)` 参数传入。
- `RsaUtil.wrapException` 用 `Supplier` 无法抛受检异常，必须用 `Callable` + `.call()`。
- AesUtil 的 `iv` 字段有 `@Setter`，误删会导致 AesUtilTest 编译失败。
- 同一测试类里方法名不能重复（TreeUtilTest.buildFromEmptyList、
  HttpUtilTest.testUrlIsNull），加用例前先 grep 确认。
- AesUtilTest 里的 Base64 密钥 "MDEyMzQ1Njc4OTAxMjM0NTY3ODkwMTI=" 解码后是
  23 字节（非法），测密钥长度相关行为要用 `new byte[16]`。
- 隔离加载的类不要硬编码 `target/test-classes` 相对路径取字节码，
  应从 `Xxx.class.getProtectionDomain().getCodeSource().getLocation()` 取，
  否则 surefire 工作目录不同会 `ClassNotFoundException`。
- 跨线程共享默认 Locale 的用例（TurkishLocaleTest）必须用 try/finally 恢复，
  否则污染同 JVM 内的其他用例。
